# 任务排序与台账口径（项目级）

> 排序的唯一真源是 `docs/design/审批与中断恢复优化规划.md` **§8.3**。本文件只写它最容易被
> 违反的几条与回写规则，**不复制顺序表**——复制出来就是第二份真源，必然与第一份漂移。
> 与 §8.3 冲突时以 §8.3 为准，并先把冲突写进该节再动手。
> 本文件只声明口径，不改动任何产品代码、测试与既有文档。

---

## 1. 状态只能由证据给出

- `docs/design/审批与中断恢复优化规划.md` §8 执行台账表是任务状态的**唯一真源**；§4 卡内的
  「状态」字段不单独维护，以表为准。
- **代码已在树中而台账仍写「待分派」，按最高优先级缺陷处理**：先把状态改成「已落地待审」
  再复验，不许当没做过重做一遍。判据是 `git status` 里能看到落点文件，不是记忆。
- reviewer 未给出结论、其子 agent 失败或超时的任务，不得标「reviewer 通过」。
  执行者自跑 `pytest` 全绿只是准入条件，不是验收结论。

## 2. 开工前先看 §8.3 的前置事实

工作树未提交文件的规模、`router.py` 上未定稿的 diff、已落地但未登记的任务——
这三项决定当前能不能取数。**没有提交边界时，任何 `pytest` 读数都不许写进台账。**
取数前先答三个问题：这批改动属哪个任务、上一个提交是什么、树里有没有别的批次的在飞改动。

## 3. 五条不许破的约束（细则见 §8.3）

1. `agentix/application/agents/router.py` 上的任务**只许串行**：T8 复验 → T29 → T30。
2. **M2 等量验收窗口内不派任何新增用例的任务**（T28、T17、L 组都算）；它验的是
   「前后全量 passed 数相同」，多一条新用例就核不出来。
3. **全量基线只 re-cite 一次**，在收尾批；中间不许边做边改 `README.md` §11。
4. **T24 在 Q10 裁决前不派**：只做接口预留而接不上线，落地即负债。
5. **M4 在 M3 之后**（路线图 §8：内核合一、退出原因归一、事件出内核、四接缝，再加干预管道 fail-closed、工具输出上限、压缩增量）。M4 改的是循环本体，
   M3 未收口时两侧同时变、出问题分不清哪边；M4 加用例，也不许落在 M2 的等量验收窗口内。

## 4. 规划改了，台账必须同批改

代码行为变更除 `AGENTS.md`「文档同步面」清单外，若牵动任务状态或排序，**必须同批更新**：

- `docs/design/审批与中断恢复优化规划.md` §8 执行台账（状态、实测读数、偏离原因）；
- `docs/design/审批与中断恢复优化规划.md` §8.3（顺序或约束有变时）；
- `docs/design/性能与优化路线图.md` §6.4 / §7.2 / §8.3（仅在跨组次序或 L/M 归属变化时，且只写指针）；
- `docs/design/性能与优化路线图.md` §7 与 §8 的方案面（仅当 M1–M3 / M4-a…g 的范围、工时或验收变化时）；
- `docs/architecture/分层架构与依赖规则.md` §7.6（仅当 M4 的落位约束变化时）。

> 编号口径：路线图的 **M1–M4** 与 `docs/migration/` 下 Stage M 的 **M0–M6** 是两套编号。
> 说「路线图 M4」指 Agent 内核那一项，说「Stage M M4」指控制平面迁入 `runtime/control_plane.py`。

**规划改了而台账没改，就是「实施与规划不一致」的起点。** 反过来，台账里出现规划之外的
新任务，另立条目编号，不占用 T 序号，也不得悄悄并入某个已通过的任务。

## 5. 架构守卫的两条口径（M1 落地时照此写）

- **每条例外必须写理由**：允许集里每条「包 → 包」都带理由，没有理由的例外不许合并。
- **登记不许腐化**：允许集里列出、但实际已不存在的边，断言必须红，逼着把它删掉。只做棘轮
  （只减不增）只能保证「不变宽」，保证不了「该收的没收」，白名单会缓慢腐化。
- 细则见 `docs/architecture/分层架构与依赖规则.md` §7.3 第 4 步；M1 的验收列已按这两条改写。

## 6. 派单件内部口径冲突：定稿处方优先

- 批次派单件里「定稿处方逐字节照用」与「允许路径清单」互斥时，**以定稿处方为准**；路径清单
  只用于校验新增文本可解析，不构成改写处方的授权，也不得据清单成员资格否决处方文本。
- `.tmp/` 下的输出件不在通用文档守卫的扫描前缀内，其反引号路径沿用既有写法即可；不为凑清单
  改写已定稿文本，也不为压低读数给历史行追加完成标记。
- 同一批次发现两条硬边界互斥：停下报原文，由编排方裁决；裁决记入当日日志与收尾报告，历史
  派单件、执行报告与台账按「不改史」保持原样，**不许自行放宽任一判据**。
- 收尾范围判据只取收尾范围探针脚本的 16 标记现值尺；脚本里的 11 标记短清单是历史对照尺，
  两套标记集互不包含，读数不要求相等，不得据其非零值判台账未闭合。
