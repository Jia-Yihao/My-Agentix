- **运行时写代码执行（code exec）默认关，开着也不构成笼子**：`CODE_EXEC_ENABLED` 默认 `false`；
  关着时路由不产 `code-query`、`code_agent` 节点不可达、`code_execute` 工具零注册，**与基线逐位等价**。
  开着时它**复用** subprocess 档已经买到的闸（三道资源闸 / 环境白名单 / 可杀进程组），
  **不额外买到任何隔离**——**仍不隔离文件系统与网络**（ADR-0007 登记的 ⑰/T3 残留），
  **仅 POSIX 可用**，非 POSIX 平台 fail-closed 拒绝执行、**永不降级为进程内执行**。
  **它要真跑起来需要四个开关同时到位**：业务总闸 `CODE_EXEC_ENABLED` +
  执行位置端口 `EXECUTION_SANDBOX_ENABLED` + 档位实现 `TOOL_SANDBOX_SUBPROCESS_ENABLED` + POSIX 平台；
  **只开业务总闸跑不起来**，缺哪一闸那次调用就**失败并说明原因**。
  四条容易踩的操作口径：① `code_execute` 声明 `risk_level="L2"`，**而 `TOOL_SELECTION_MAX_RISK` 默认 `L1`**——
  开了 `TOOL_SELECTION_ENABLED` 又没把上限提到 `L2`，执行器的风险闸会把这次调用**拒掉**
  （治理层终局，不进自愈循环），现象是「风险等级超过策略上限」而不是「代码跑不起来」；
  ② `HUMAN_REVIEW_ENABLED` 开着时该工具走**人工审批**（`code_execute` 命中 `execute` 审批词 ⇒ 有效风险 HIGH），
  **无批准人就是拒绝**；③ `code_execute` **不进 LLM 可见工具面**（由 `code_agent` 节点直接经
  `ToolExecutor.execute` 调用）——所以它不受 `DISABLED_TOOLS` 的**声明层**裁剪管，
  但仍受执行侧权限兜底管；**所有 LLM 可见拼装点都无条件排除它**：任务拆解的
  「可执行工具菜单」（会写进拆解提示词，模型看得见就能点名调用——那等于把"跑任意代码"变成一次普通的工具选择）、
  以及按**注册表全集**导出的 OpenAI schema 拼装点（`list_tool_specs` / `list_openai_tools` /
  `get_tool_spec`——`register_handler` 会把它的 spec 顺带登记进注册表，不筛就会漏出去）。
  判据**只有一个源**：`agentix/tools/definitions.py::NON_LLM_VISIBLE_TOOL_NAMES`。
  ④ 工具级超时（`timeout_ms` = 150 秒）是**兜底**闸，代码级超时
  （`timeout_s`，1–120 秒，缺省取配置 `CODE_EXEC_TIMEOUT_S`）才是**内层**闸：代码超时先到会返回
  `timed_out=True`（可解释），工具级超时只在治理链整体卡死时兜底。
  ⑤ **「非 LLM 可见工具」不得声明成 L0**——这是**两条承诺的交叉处**，不是风格要求：
  LLM 可见面靠**名字集合**拦（`agentix/tools/definitions.py::NON_LLM_VISIBLE_TOOL_NAMES`），
  而 MCP 导出面靠**等级**拦（`agentix/capabilities/mcp/tool_source.py` 只导出
  `risk_level == "L0"` 的工具，压根不认识那个集合）⇒ 等级一旦写成 L0，
  两个导出面对同一个工具给出的答案互相矛盾，它会从 MCP 导出面漏出去。
  守卫见 `tests/test_p131_code_exec.py::TestNonLlmVisibleToolsAreNotL0`。
  取证指针：这一档的隔离承诺已在 **Linux 容器真机取证过**（2026-10-26，镜像 `python:3.12-slim`
  / Python 3.12.15，root 与非 root 两轮 p131 各 39 passed / 0 skipped，并配了变异反证），
  步骤与当轮真输出见 [subprocess 沙箱验证 Runbook](runbooks/子进程沙箱取证.md)。
  机制级口径见 [.qoder/rules/code-exec.md](../.qoder/rules/code-exec.md)。
