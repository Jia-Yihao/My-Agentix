# 发布与回滚 Runbook（P1 部署收口）

> 范围：把一个版本**部署到目标环境**并**安全回滚**的操作面。
> 版本号规则、tag、CI 自动发布见 `docs/版本管理策略.md`；环境配置差异见 `.env.{development,staging,production}.example`；密钥管理见 `密钥管理.md`。

## 1. 发布前置检查

```bash
# 1) 版本一致性（三处同步 + CI version-consistency 作业）
python scripts/bump_version.py --check

# 2) 测试全绿（本地基线以 README §11 的实测数字为准）
pytest tests -q            # 参考基线：见 README §11（本文档不重复该数字，避免两处漂移）

# 3) 构建验证（镜像可构建 + compose 配置合法）
docker compose config -q
docker build --target server .
```

> ⚠️ **本机验证待办（2026-09-21）**：`docker compose config -q` 已通过；`docker build --target server` 因本机 Docker Desktop 未运行 + 宿主代理（`127.0.0.1:<port>`，端口随启动变化）未注入守护进程而暂缓——Docker Desktop 默认不走宿主 shell 代理，拉取基础镜像会直连超时。验证前需在 Docker Desktop Settings → Resources → Proxies 配置当前代理端口，或关闭代理直连。

## 2. 部署步骤

```bash
# 1) 目标机准备 .env（以对应环境 example 为母本；密钥经密钥管理注入，不入库）
# 2) 拉取代码到发布 tag
git fetch --tags && git checkout vX.Y.Z

# 3) 构建并滚动启动（后端镜像变更是重建而非 in-place）
docker compose build backend retrieval-worker kb_ingest neo4j
docker compose up -d

# 4) 等待健康（start_period 后观察）
docker compose ps                      # 全部服务 healthy / running
```

## 3. 部署验收（健康检查链）

| 层 | 检查 | 通过标准 |
|---|---|---|
| 容器层 | `docker compose ps` | 13 服务无一 `unhealthy`/`restarting`（worker 用 celery inspect ping，etcd 用 etcdctl endpoint health，kb_ingest 用 /health） |
| 进程层 | `curl :8000/liveness` | 200（进程活着，无依赖检查） |
| 依赖层 | `curl :8000/readiness` | 200 且关键依赖（redis 等）healthy |
| 业务层 | `curl :8000/health` | 200，`services` 字段无 down |
| 冒烟层 | `/metrics` 有抓取值；发一条测试对话走通 SSE | 端到端可用 |

**任一层失败 → 进入回滚决策**（不要在目标环境上现场 debug）。

## 4. 回滚流程（按影响面从轻到重）

### 4.1 仅应用回滚（最常见：新版本代码问题）
```bash
# 回到上一个 tag 重建 backend 镜像并滚动替换
git checkout <previous-tag>
docker compose build backend retrieval-worker
docker compose up -d backend retrieval-worker
docker compose ps          # 复验第 3 节验收链
```
适用前提：**无破坏性 schema 迁移**（本项目以 SQLAlchemy 元数据为主、无 Alembic 版本链，应用回滚通常安全）。

### 4.2 配置回滚（新配置项引发问题）
- 定位问题配置 → 在 `.env` 恢复上一值 → `docker compose up -d`（多数开关为观测/降级设计，改配置即回行为）；
- feature flag 类（CONTEXT_*/GROUNDING_*/MEMORY_CARDS_ENABLED 等）默认即零行为变化，逐项复位即可。

### 4.3 数据回滚（仅限灾难场景，需授权）
- 备份/恢复走既有脚本：`scripts/db/backup_databases.ps1` / `scripts/db/restore_databases.ps1`；
- **警告**：恢复快照会丢弃快照之后的全部写入，必须先停写（`docker compose stop backend retrieval-worker kb_ingest`）并获明确授权。

### 4.4 代码库回滚（开发机事故兜底）
- 每阶段收口刷新 git bundle：`git bundle create agentix_main_latest.bundle --all`；
- 恢复：`git clone agentix_main_latest.bundle`（bundle 记录完整历史，verify 后可直接工作）。

## 5. 发布记录

每次发布在 `CHANGELOG.md` 对应版本段补一行部署注记（日期、目标环境、镜像 digest、验收结果），回滚同样记录原因与恢复点。
