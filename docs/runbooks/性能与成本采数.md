## 采数步骤（PowerShell）

### 第 1 步：环境就绪

全栈环境按 `docs/runbooks/评测基线录制.md` 第 1–2 步准备（LM Studio +
基础设施容器），并记录模型快照与温度——**数字与模型快照绑定，换模型须重测**。

**宿主直跑的三个前置**（2026-10-23 实测，每一个都让人以为是代码坏了）：

1. **必须用仓库 `.venv` 的解释器**。系统 conda 环境缺 `lightrag`，启动即
   `ModuleNotFoundError: No module named 'lightrag'`。
2. **`.env` 里的主机名是容器内网名**，宿主进程解析不到 ⇒ `psycopg.OperationalError:
   [Errno 11001] getaddrinfo failed`。要在启动时显式覆盖，且**先确认这些变量在
   `.env` 里带不带值**再决定是否打印（`docker compose config` 会把真实 `.env` 展开到
   stdout，密码会跟着出来）：
   `DATABASE_URL` / `REDIS_URL` / `REDIS_CACHE_URL` / `REDIS_CHECKPOINT_URL` /
   `REDIS_CELERY_URL` 换 `127.0.0.1` + compose 映射端口（postgres `15432`、redis `6379`）。
3. **库名要现查，别信本地那份 `.env`**：本机曾长期留着 `…/legelbot`（包重命名前的存量库名，
   CHANGELOG 里写明"保留存量本地库名"，所以模板不会被自动改写）。先问库里的实际名字：
   `docker exec <postgres 容器> psql -U postgres -lt`，本机应当是 `agentix`。照抄 `.env`
   会连到一个不存在的库。（本次已把这台机器的 `.env` 改成 `agentix`，`.env` 属 gitignored，
   不进版本库；模板 `.env.example` 本来就是对的。）

另外两件事在这一步就该确认，否则第 2 步跑出来的是废数据：**LLM 侧有没有余额**
（DeepSeek 402 会让 router 与多工具分支全走兜底，单请求 0 token，采到的"时延"是兜底时延）
和**embedding 服务在不在**（LM Studio 默认 `127.0.0.1:1234`；不在 + 无活动索引产物 ⇒
检索报 `degraded: indexing`，知识分支只剩固定文案）。

### 第 3 步：TTFT P50/P95（Prometheus 查询）

浏览器打开 `http://localhost:9090`（compose 默认 `PROMETHEUS_PORT=9090`），
执行 PromQL：

```promql
histogram_quantile(0.50, sum(rate(agent_ttft_seconds_bucket[10m])) by (le))
histogram_quantile(0.95, sum(rate(agent_ttft_seconds_bucket[10m])) by (le))
```

或直接从轨迹包统计（替代法）：`TRAJECTORY_SINK=jsonl` 落盘后，对每帧
`ttft_ms` 字段做 P50/P95 统计：

```powershell
# 轨迹 JSONL 中抽 ttft_ms 排序取分位（示例：对收集到 csv 后用 Excel/脚本统计）
Select-String -Path evals\results\*.jsonl -Pattern '"ttft_ms":\s*(\d+)' | ForEach-Object { $_.Matches[0].Groups[1].Value } | Sort-Object {[double]$_}
```

### 第 4 步：单会话平均 token

```promql
sum(increase(llm_tokens_total[30m])) by (type)
```

分母**必须按端点过滤**，同窗口的流式请求数是：

```promql
sum(increase(http_requests_total{endpoint="/api/v1/chat/stream"}[30m]))
```

两条都是 2026-10-23 在临时 Prometheus（9091 抓取宿主 8011）上真跑过的表达式。
两个坑，都实测踩过：

1. 标签名是 `endpoint`，**不是** `path`——`... by (path)` 不报错，只会把所有序列
   折成一个空标签 `{}`，看起来"有数"其实是全量混在一起；
2. 不加过滤直接 `sum(increase(http_requests_total[30m]))` 会把 **Prometheus 自己
   抓 `/metrics` 的请求**算进来（实测同窗口 `/metrics` 225 次 vs 业务请求 21 次，
   分母虚高 10 倍，单请求 token 直接被算小一个数量级）。

`route_accuracy` 是 eval 报告里的**比率**（`evaluate()` 的 summary 键），不是计数器，
不能当请求数用。按 `branch=chat_stream` 聚合 `UsageRecord` 可得会话级明细。

## 成本 A/B 对比（P2-4）

优化项建议选 `LG_TOKEN_HISTORY_BUDGET`（token 级历史窗口，默认 0 关）：

1. 固定模型快照 + 温度；
2. flag-off 一轮 `--record`（输出文件记为 a.jsonl）；
3. `.env` 开 `LG_TOKEN_HISTORY_BUDGET=<预算>` 后再一轮（b.jsonl）；
4. 配对显著性：

```powershell
.\.venv\Scripts\python.exe evals/run_eval.py --compare evals\results\a.jsonl evals\results\b.jsonl
```

5. 从两轮 `UsageRecord` / 轨迹分别统计平均 token/会话；
6. 报告四段模板（环境 / 方法 / 数字 / 结论）落 `evals/results/` 目录下
   （文件名 cost_ab_report.md，属执行期产物、仓库中不预先存在）；
   显著性 CI 含 0 时**如实写"不显著（噪声区间）"**——工具已内建该标注，别挑数字。
