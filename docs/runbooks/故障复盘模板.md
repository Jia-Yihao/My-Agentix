# Postmortem 模板 + 首批案例

> 每修一个 P0/P1 级缺陷，写一条记录（企业级评估 §8.2）。

## 模板（复制此节）

```markdown
### [日期] 事故标题（一句话）
- **级别**：P0 / P1 / P2
- **现象**：用户/监控看到了什么
- **根因**：技术根因（5 Why 收敛到一处）
- **修复**：commit / PR + 关键改动
- **检出方式**：怎么发现的（告警 / 测试 / 人肉）——目标：全部转为前两者
- **防复发**：补了什么测试 / 告警 / 流程
- **耗时**：定位 X 分钟 + 修复 Y 分钟
```

---

### [2026-09-20] TraceIdMiddleware 对 4xx 响应写 body 导致 500
- **级别**：P1
- **现象**：部分错误响应变成 500，真实错误码丢失
- **根因**：中间件尝试回写已消费的 streaming body
- **修复**：R4.6——中间件改为 header 注入 trace_id，不再触碰 body
- **检出方式**：e2e 测试失败
- **防复发**：trace_id 回显契约测试
- **耗时**：定位 30 分钟

### [2026-09-20] 限流器已实现但编排域全部路由未挂载
- **级别**：P0（安全纵深缺口）
- **现象**：测试数据编排域无限流保护，知识域聊天路由有限流——保护不对称
- **根因**：限流能力最初只为检索域实现，编排域接入时未同步
- **修复**：`64ef95d` 全局 ASGI 中间件 `GlobalRateLimitMiddleware` 挂最外层
- **检出方式**：企业级评估 grep 实证（"已实现的限流器没盖住全部入口"）
- **防复发**：`rate_limit_triggered_total{scope}` 指标 + My AgentixRateLimitStorm 告警；评估报告将"横切能力必须全覆盖"列为检查项
- **耗时**：评估发现 → 修复 1 天

### [2026-09-20] 分页切片残留变量（F821 未捕获即上线）
- **级别**：P1
- **现象**：`vector_db.py` 分页路径 `result[start:end]` 引用已删除变量
- **根因**：重构后切片变量残留；仓库历史无 lint 门禁
- **修复**：`c303535` 清零 ruff 门禁（11 项），该处改回 `result`
- **检出方式**：lint 首跑（环境修复后第一次全仓扫描）
- **防复发**：ruff 进 CI 阻断门禁；本次补齐全链路 e2e 的前置
- **耗时**：定位 5 分钟（lint 直指行号）
