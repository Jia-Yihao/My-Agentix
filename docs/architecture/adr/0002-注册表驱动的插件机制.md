# ADR-0002：采用注册表驱动的可插拔扩展机制

- **状态**：已采纳
- **日期**：2026-09-11
- **决策者**：My Agentix 维护者
- **相关**：[扩展机制.md](../扩展机制.md)、[接口与契约.md](../接口与契约.md)

---

## 背景 (Context)

系统中存在多类「同一抽象、多种实现」的组件：

| 组件 | 实现变体 | 原状 |
|------|---------|------|
| 工具 (Tool) | cypher / predefined / graphrag / text2sql | 硬编码列表散布在 4 个文件 |
| LLM Provider | OpenAI 兼容 / Anthropic / vLLM … | `get_llm_client` 硬编码 `ChatOpenAI(...)` |
| Embedding Provider | OpenAI / DashScope / 本地 BGE | `KnowledgeService` 硬编码构造 |
| Reranker Provider | Cohere / Jina / Voyage / Custom | `Reranker.rerank` 内 `if/elif` 链 |

后果：**新增一种实现需要改动调用链**（违反开闭原则），且「配置写错」与
「功能异常」难以区分。

---

## 决策 (Decision)

引入**注册表驱动的可插拔机制**，分两层：

### 1. 通用容器 `PluginRegistry`

`agentix/infrastructure/registry.py` 提供零依赖的 `PluginRegistry[T]`：

```python
register(name, factory, *, override=False)   # 注册
factory(name) -> Callable                    # 取工厂（不调用）
get(name, *args, **kwargs) -> T              # 解析并调用
maybe_get(name, ...) -> Optional[T]          # 可选解析
names() / has() / unregister() / clear()     # 内省
```

- 重复注册默认**报错**（而非静默覆盖）——这条是 `PluginRegistry` 的语义；`ToolRegistry` 的同名再声明走另一条路径：默认覆盖 + 点名告警，严格模式可选、默认关（PROJECT_SPEC §24.2 G14）
- 解析未注册的名字抛 `RegistryError`（继承 `KeyError`，兼容既有 `except`）

### 2. 各领域注册表

| 注册表 | 位置 | 解析失败语义 |
|--------|------|-------------|
| `ToolRegistry` | `infrastructure/tools/definitions.py` | 报错（工具缺失属编程错误） |
| `llm_providers` | `infrastructure/llm/provider_registry.py` | **fail-fast**（核心链路） |
| `embedding_providers` | `infrastructure/knowledge/embedding_providers.py` | **fail-fast**（核心链路） |
| `reranker_providers` | `infrastructure/knowledge/reranker_providers.py` | **降级**（可选增强） |

> 终态勘误（2026-10-04）：`ToolRegistry` 现规范位 `agentix/tools/definitions.py`（infrastructure/tools 与 capabilities/tools 已随 M6 删除）；`llm_providers` 仍在 `infrastructure/llm/provider_registry.py`；embedding / reranker 注册表现归检索域（`agentix/retrieval/infra/embedding/`、`agentix/retrieval/infra/rag/rerank.py`，原 infrastructure/knowledge 已删）。ADR 正文保留决策原貌，读实现按本行跳转。

### 3. 差异化失败语义（刻意的）

- **核心组件**（LLM / Embedding）：配置了未注册的 Provider → 抛错。
  理由：静默退回默认实现会让「配置写错」表现成「模型/检索行为异常」，极难定位。
- **可选增强**（Reranker）：未注册 → warning + 截断返回。
  理由：Reranker 缺失不影响正确性，不应因配置问题打断整条问答。

---

## 理由 (Rationale)

| 考量 | 说明 |
|------|------|
| **开闭原则** | 新增实现只改 1 处（注册点），调用链零改动 |
| **可发现性** | `names()` 可自省当前可用实现，便于 `/ops` 与报错提示 |
| **显式失败** | 未注册名字报错并列出可用项，而非静默降级 |
| **可测试性** | 注册表可 `unregister`/`clear`，测试隔离容易 |
| **零依赖** | 通用容器仅用 stdlib，可被任意层复用 |

### 备选方案与取舍

| 方案 | 否决理由 |
|------|---------|
| 继续用 `if/elif` 链 | 新增实现要改调用链；无自省能力 |
| 引入第三方插件框架（pluggy 等） | 新增依赖；本项目规模无需完整插件生命周期 |
| 纯依赖注入容器 | 需在装配期显式绑定，配置驱动的「按名解析」不自然 |

---

## 后果 (Consequences)

### 正面

- 新增 LLM Provider：注册一项 + 设 `LLM_PROVIDER`，调用链零改动
- 新增 Reranker Provider：注册一个 handler，`Reranker.rerank` 零改动
- 工具集可通过 `DISABLED_TOOLS` 配置裁剪，无需改代码
- 配置错误可被快速定位（报错列出可用项）

### 负面 / 成本

- 多了一层「名字 → 工厂」的间接性
- 注册时机需注意：内置 Provider 采用**懒注册**（`ensure_llm_providers_registered`），避免 import 期副作用

### 缓解

- 注册表 `docstring` 明确契约与失败语义
- `tests/test_plugin_registry.py`（25 例）覆盖注册/解析/覆盖/隔离/失败语义
