# ADR-0003：配置声明单一事实来源（Pydantic Settings）

- **状态**：已采纳
- **日期**：2026-09-11
- **决策者**：My Agentix 维护者
- **相关**：[配置管理.md](../配置管理.md)

---

## 背景 (Context)

项目早期存在配置来源分散的问题：

- 主配置 `agentix/config/settings.py`
- `kb_ingest/kb_service/core/config.py`（独立的一套 `os.getenv`）
- `kb_ingest/.env`（独立的环境文件）
- `pyproject.toml` 无 `dependencies`（依赖声明与实际不符）

> **2026-09-11 更新（P2-4 已收口）**：上述「三套配置」中的依赖与版本部分已解决——
> `pyproject.toml` 补齐 `[project.dependencies]`、`lightrag-hku` 补上界、
> `requires-python` 统一为 `>=3.10,<3.11`。
> `kb_ingest` 是**独立部署**的容器（独立 Dockerfile / requirements.txt），
> 其配置边界刻意保持为**环境变量**（不引入主应用 settings，避免让接入服务
> 依赖主应用的必需密钥）；其环境变量契约现由 `kb_ingest/.env.example`
> 单一维护，并由 `tests/test_p35_config_governance.py` 双向校验防漂移。
> 主应用侧另新增 `agentix/config/selfcheck.py`：启动时比对 `.env` 与
> `.env.example` 的**字段集合**，缺项告警（只比键不比值，避免密钥进日志）。

后果：

- **事实来源脱节**：同一个配置项在不同模块含义可能漂移
- **默认值不一致**：`requires-python` 声明 `>=3.9` 但 README 要求 3.10
- **敏感项缺失**：`.env` 缺 `SECRET_KEY` 等，运行时随机生成导致鉴权失效
- **业务代码散落 `os.getenv`**，难以审计与集中校验

---

## 决策 (Decision)

采用 **Pydantic Settings 作为配置的单一事实来源**：

1. **集中声明**：所有运行时配置定义在 `agentix/config/settings.py` 的 `Settings` 类
2. **分层覆盖**：进程环境变量 > `.env` 文件 > 代码默认值
3. **禁止散落**：业务代码统一 `from agentix.config import settings`，禁止 `os.getenv`
4. **别名兼容**：历史配置名用 `AliasChoices` 保留（如 `OPENAI_MODEL` → `LLM_MODEL`）
5. **敏感项校验**：`SECRET_KEY` 生产缺失直接启动失败（`resolved_secret_key`）
6. **特性开关**：所有架构改造项提供配置开关，回滚不改代码
7. **依赖声明同步**：`pyproject.toml` 的 `[project.dependencies]` 与 `requirements.txt` 同步
8. **版本号三处一致**：`scripts/bump_version.py` 维护并校验

---

## 理由 (Rationale)

| 考量 | 说明 |
|------|------|
| **类型安全** | Pydantic 在启动期完成类型转换与边界校验（`ge=`/`le=`） |
| **可自省** | `Settings` 字段即配置清单，可生成文档 |
| **可测试** | 测试可 monkeypatch `settings` 单例 |
| **审计友好** | 单一文件即可审计全部配置项 |
| **安全默认** | 敏感项无默认值；特性开关默认关闭 |

### 备选方案与取舍

| 方案 | 否决理由 |
|------|---------|
| 纯 `os.getenv` 散落 | 无类型校验、无自省、难审计 |
| YAML 配置文件 + 自研加载 | 需自研校验逻辑；且环境变量覆盖不自然 |
| Dynaconf / Hydra 等配置框架 | 新增依赖；本项目规模无需多环境配置分层 |

---

## 后果 (Consequences)

### 正面

- `.env.example` 与 `settings.py` 字段一一对应，可人工比对
- 生产缺 `SECRET_KEY` 启动即失败（不再静默随机生成）
- `requires-python` 统一为 `>=3.10,<3.11`，与 README 一致
- `pyproject.toml` 补全 `dependencies`，事实来源与包声明同步

### 负面 / 成本

- `Settings` 字段较多（按功能分组缓解）
- 历史别名的兼容 property（如 `OPENAI_API_KEY`）是**只读**的，
  测试 monkeypatch 需改底层字段（已在文档中说明）

### 缓解

- `settings.py` 按功能分组并逐项注释
- `.env.example` 提供带注释的完整样例
- 启动期自检输出关键配置状态（不打印密钥值）
