# Run API 客户端重试幂等契约（`Idempotency-Key`）

> 本文档是 `POST /api/v1/agents/runs` 幂等语义的**对外契约真源**（规划 Q8 裁决：
> `Idempotency-Key` header + 同键重放返 200 复用原 run）。契约先于实现提交。
> 对应任务卡：`docs/design/审批与中断恢复优化规划.md` T20。
>
> **分层声明（不得混写）**：本契约是**客户端重试幂等**——防的是"调用方超时重试
> 导致同一创建意图被执行两次"。它与审批侧的"一次批准一次执行"
> （`agentix/tools/gateway/human_review.py` 的批准消费语义）是**两层不同的幂等**，
> 各自独立成立，任何一方不得援引另一方作为自己的保证。

## 1. 适用范围

| 项 | 内容 |
|---|---|
| 端点 | 仅 `POST /agents/runs`（创建运行）。GET 查询与 cancel 本身幂等，不需要键 |
| 实现位置 | `agentix/interfaces/http/v1/runs.py`（进程内键存储 + header 解析） |
| 运行登记 | 复用 `agentix/runtime/control_plane.py` 的 `ControlPlane.spawn`（`run_id` 服务端 `uuid4` 生成，本契约不改变生成方式） |

## 2. Header 语义

- **header 名**：`Idempotency-Key`（大小写不敏感，HTTP header 常规）。
- **无 header ⇒ 行为与现状逐位等价**：不生成隐式键、不改变响应体形状、
  不新增任何可观测差异（硬性纪律 1，Strangler 口径）。
- **键取值**：调用方提供的任意字符串，**1–256 个字符**（量纲是字符数）。
  - header 存在但Strip 后为空 ⇒ `400 INVALID_IDEMPOTENCY_KEY`；
  - 超过 256 字符 ⇒ `400 INVALID_IDEMPOTENCY_KEY`。
  - 错误响应**只说为什么被拒，不回放键内容**（纪律 6 ③ 精神：被拒输入不进响应体）。
- **登记失败的键不占用**：只有运行**真正 spawn 成功**后键才与 `run_id` 绑定。
  鉴权失败（401）、参数非法（400 `UNKNOWN_AGENT` / `INVALID_IDEMPOTENCY_KEY`）、
  准入拒绝（429）都发生在绑定之前 ⇒ 同键重试不会被一次失败请求"毒化"。

## 3. 重放语义（验收核心）

同一进程存活期内，相同键的后续请求（无论**先后**还是**并发**到达）：

1. 返回 **HTTP 200**（不是 201/409——裁决就是 200 复用）；
2. 响应体 `data.run_id` 为**首次成功创建时的那个 `run_id`**；
3. **不二次执行副作用**：不再 `spawn`、不再起执行协程；
4. 响应体形状与首建完全一致（`run_id` / `agent` / `status` 三字段，不加新字段）。
   `status` 反映该运行**当前**状态（首建瞬间为 `pending`，重放可能已是
   `running`/终态）；运行记录已被 ControlPlane 的有界保留窗（`max_runs`）淘汰时，
   回落值为 `pending`，且进度无从核证（`GET /agents/runs/{run_id}` 返 404）——
   调用方应把"200 + status=pending + GET 404"组合理解为"窗口内复用但运行记录
   已出 ControlPlane 的有界保留窗"；
5. 调用方无需（也无法从响应体上）区分"首建"与"复用"——两者本就该等价；
   需要确认进度走 `GET /agents/runs/{run_id}`。

**并发判据**：同一键的多个并发请求**只创建一个运行**。原子性成立的形态是
**单一事件循环**：本端点为 `async def`，FastAPI 恒在事件循环线程执行，实现上
"检查键 + 登记键→run_id"临界区内零 `await`，在该形态内即构成互斥——只靠
"查了再写"的两步写法就是竞态。外层 `threading.Lock` 只是存储层对任意调用线程
的**防御性守卫**；**本契约不为"路由被下放线程池调用"的部署形态作保证**——该
形态下实现工厂（spawn+bind）里的 `asyncio.create_task` 要求调用线程有运行中的
事件循环、`ControlPlane` 亦无线程安全原语，两层守卫都救不了。

## 4. 键存储：保证边界与生命周期（**不许超卖**）

**当前保证边界 = 进程存活期。跨重启不保证。**

键存储本轮**只在进程内存**（`agentix/interfaces/http/v1/runs.py` 内的有界 map）。
进程重启、崩溃恢复、或多副本部署下，**同键可能被再次当作新请求创建运行**——
这是已登记的已知边界，不是缺陷。持久化幂等层（跨重启成立）归 **T21**
（运行态落 Postgres），落地后本契约文档修订、保证边界上移；在此之前
**任何文档/代码注释/对外表述不得宣称"跨重启幂等"**。

三个口径（实现与本文档逐字一致）：

| 口径 | 值 | 说明 |
|---|---|---|
| TTL | `IDEMPOTENCY_TTL_S = 3600.0`（秒，自登记起算） | 过期键视同不存在 ⇒ 同键重试会**新建**运行 |
| 上限 | `IDEMPOTENCY_MAX_ENTRIES = 4096` | 超限按**登记顺序 FIFO 逐出**最旧条目；被逐出的键同 TTL 语义，重试会新建 |
| 清理 | **惰性清扫**：每次键操作时顺带删除已过期条目；无后台定时器 | 上限逐出在登记时同步执行 |

TTL/上限是**有界内存**的充要两条（调用方键是任意字符串，不设界就是无界增长）；
取值有意保守——TTL 覆盖正常客户端重试窗口（秒级到分钟级），上限按 header 键
体量（≤256 字符 + 一个 run_id）估算不足 2MB。

## 5. 可观测性（命中不得静默）

- 幂等**命中（复用）**时 `logger.info` 留痕：只输出键的 **SHA-256 指纹前 12 位**
  与命中的 `run_id`，**不输出键原文**（键是调用方提供的任意字符串，可能承载
  调用方侧的敏感语义，且属高基数内容）。
- **键内容禁止进入任何指标 label**（硬性纪律 3 高基数禁令）；本契约不新增指标，
  日志之外零可观测面变化。

## 6. 测试真源

行为契约的可执行判据见 `tests/test_p143_run_idempotency.py`：无 header 逐位等价、
同键先后/并发重放、TTL/上限清理（假时钟注入，不真等）、键不进指标 label。
