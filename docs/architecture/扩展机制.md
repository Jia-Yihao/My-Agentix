## 新增工具 (Tool)

**扩展点**：`agentix/tools/registry_init.py`

新增一个 KG 工具**只需改 1 处**——在 `_build_declarations()` 的清单里追加一项，
其余链路（`lg_builder` 的 `get_active_tools()` → `tool_selection` → `PydanticToolsParser`）
自动生效。

### 步骤

**1) 定义工具的参数 schema（pydantic 模型）**

在 `agentix/tools/kg_arg_schemas.py`（KG 工具参数 schema 的规范位，M2-4 拆边后；`application/agents/kg_sub_graph/kg_tools_list.py` 为再导出 shim，不再新增）或你的工具模块中定义：

```python
from pydantic import BaseModel, Field

class web_search(BaseModel):
    """联网检索工具的参数。"""
    query: str = Field(..., description="检索关键词")
    top_k: int = Field(default=5, ge=1, le=20, description="返回条数")
```

**2) 在声明式清单中登记（唯一改动点）**

```python
# agentix/tools/registry_init.py

def _import_schemas():
    from agentix.tools.kg_arg_schemas import (  # noqa: PLC0415
        cypher_query, microsoft_graphrag_query, predefined_cypher,
        text2sql_query, web_search,        # ← 新增
    )
    return cypher_query, predefined_cypher, microsoft_graphrag_query, text2sql_query, web_search


def _build_declarations():
    ...
    return [
        ...,
        (
            ToolSpec(
                name="web_search",
                description=(
                    "联网检索实时信息。\n"
                    "何时用：问题涉及时效性信息（最新政策、近期案例），且本地知识库无记载时。\n"
                    "何时不能用：数据条目/数据分类/示例说明查询——应走 cypher_query 或 "
                    "microsoft_graphrag_query（联网结果非法定文本，不能作为数据条目依据）；"
                    "统计类问题——走 text2sql_query。\n"
                    "注意：结果需标注来源，不得作为唯一依据。"
                ),
                parameters=web_search.model_json_schema(),
            ),
            web_search,
        ),
    ]
```

**3) 实现工具的执行节点**

在 `components/` 下新建节点，并在 `tool_selection/node.py` 的 `_TOOL_ROUTE_TABLE`
中登记 `tool_name → (goto 节点名, payload 模式)`。

> ⚠️ **`description` 必须写明「何时不能用」**——这是降低工具误选的首要手段
> （选错工具先查描述，再怀疑模型）。`tests/test_p13_registry.py` 会校验该反例存在。

### 契约要求

| 要求 | 原因 |
|------|------|
| `description` 含「何时用 / 何时不能用」 | 降低误选；有测试守卫 |
| `factory` 懒加载（不 import 期构造对象） | 避免注册期依赖 Neo4j/Redis/LLM |
| 只读工具（写操作需人工审批旁路） | 见 [SECURITY.md](../../SECURITY.md) |
| 结果分页 / 截断 | 防止大结果污染上下文（见 `domain/policies/`） |

### 裁剪工具集

通过配置 `DISABLED_TOOLS=text2sql_query,predefined_cypher`（逗号分隔）即可在运行期
裁剪工具集，**无需改代码**。

## 新增 Provider

所有 Provider 注册表基于通用容器 `PluginRegistry`（`infrastructure/registry.py`），
语义一致：`register(name, factory)` / `factory(name)` / `get(name, *args)` / `names()`。

### LLM Provider

**扩展点**：`agentix/infrastructure/llm/provider_registry.py`（注册表）
+ `agentix/application/agents/llm_factory.py`（内置 Provider 注册）

```python
# 在你的插件模块中
from agentix.infrastructure.llm.provider_registry import llm_providers

def _build_my_provider(profile, *, temperature, tags, timeout, max_retries):
    """构建函数签名契约：(profile, *, temperature, tags, timeout, max_retries) -> ChatModel"""
    from langchain_anthropic import ChatAnthropic
    return ChatAnthropic(
        model=profile.model,
        temperature=temperature if temperature != 0.7 else profile.temperature,
        timeout=timeout if timeout is not None else profile.timeout,
        max_retries=max_retries if max_retries is not None else profile.max_retries,
    )

llm_providers.register("anthropic", _build_my_provider, override=True)
```

随后设置 `LLM_PROVIDER=anthropic` 即生效。

> **失败语义**：未注册的 Provider 抛 `RegistryError`（**fail-fast**）。
> 配置写错不会被静默降级为 openai——否则会表现成「模型行为异常」，极难定位。

**角色化配置**：如需为不同角色用不同模型，修改 `llm_factory.DEFAULT_PROFILES`
（`router` / `planner` / `tool` / `summarizer` / `general` / `hallucination`）。

### Embedding / Reranker Provider

> **R1.8 归档说明**：旧 `embedding_providers` / `reranker_providers` 注册表
> （原位于 `agentix/infrastructure/knowledge/`，目录已随清理删除）已随旧 RAG 实现整体归档至
> `archive/legelbot-knowledge/`。当前 Embedding 由 `agentix/retrieval/infra/embedding/client.py`
> 统一提供（OpenAI 兼容 `/embeddings` 端点，覆盖 OpenAI / DashScope / vLLM / LM Studio）；
> 重排内置于 `RetrievalPortAdapter`（RERANKER_ENABLED / RERANKER_MODEL 配置）。
> 如需新增 Embedding 后端，扩展 retrieval 域 `client.py` 的构建路径；下述旧注册表
> 用法仅适用于归档代码的历史参考。

## 新增 Agent 子图

**扩展点**：`application/agents/kg_sub_graph/agentic_rag_agents/workflows/multi_agent/`

参考现有 KB 子图的结构（P1-1 拆分后的目标形态）：

```
multi_agent/
├── kb_workflow.py        # 装配：StateGraph + 节点 + 边（< 150 行）
├── kb_states.py          # 状态定义（TypedDict + 归约器）+ 配置 dataclass
├── kb_formatters.py      # 纯函数（格式化，易单测）
├── kb_nodes/             # 每个节点一个文件
│   ├── guardrails_node.py
│   ├── router_node.py
│   ├── local_search_node.py
│   ├── external_search_node.py
│   └── finalize_node.py
└── prompts/kb_prompts.py # prompt 常量（稳定前缀，利于 KV Cache）
```

### 节点签名约定

```python
async def my_node(state: MyState, *, config: RunnableConfig) -> dict:
    """返回**状态增量**（不修改入参），或返回 Command 做条件跳转。"""
```

### 关键约定

| 约定 | 原因 |
|------|------|
| 节点返回**增量 dict**，不改入参 | 避免副作用传染，便于单测 |
| 需要逐 token 流式输出的回答节点**必须转发 `config`** | 否则 `on_chat_model_stream` 不冒泡（真流式失效） |
| **内部编排节点不得转发 `config`** | 否则内部推理碎片会外泄给用户 |
| 回答节点名需加入 `ChatService._STREAM_FORWARD_NODES` 白名单 | 控制哪些节点的 token 可见 |
| 格式化逻辑抽为**纯函数** | 零依赖单测 |
| prompt 提为模块级常量 | 稳定静态前缀 + 单一事实来源 |

### 装配与注册

```python
# kb_workflow.py
def create_my_workflow(...) -> CompiledStateGraph:
    builder = StateGraph(MyState, input=MyInputState, output=MyOutputState)
    builder.add_node("guardrails", create_guardrails_node(...))
    ...
    builder.add_edge(START, "guardrails")
    return builder.compile()
```

在主图中引用（`lg_builder.py`），并在 `router.py` 的 `route_query` 增加分支。

> **编译缓存**：若子图装配开销较大，用 `@lru_cache` 按「可哈希配置指纹」缓存
> （参考 `lg_builder._get_compiled_multi_tool_workflow`）。运行时对象（LLM/图）
> **不参与 key**，由闭包或单例在运行时获取。

## 新增领域策略

**扩展点**：`agentix/domain/policies/`

领域策略是**纯函数**（无副作用、无 I/O），因此可零依赖单测。

```python
# domain/policies/my_policy.py
def should_degrade(error_code: ErrorCode) -> bool:
    ...
```

**词汇表 vs 策略的分区**：
- `domain/errors.py` = **词汇表**（有哪些错、属哪一类）
- `domain/policies/` = **判定函数**（遇到这类错该怎么做）

在 `policies/__init__.py` 中 re-export。注意：`domain` 层**禁止** import
`infrastructure` / `interfaces` / `application`（守卫：`test_p17_domain_layer.py`）。

## 新领域适配

My Agentix 的定位是**以 Agent 内核 + RAG 等多路检索为核心的综合服务平台**，
并通过领域适配层保持**可迁移性**。迁移步骤：

| 步骤 | 内容 | 参考 |
|------|------|------|
| 1. 领域数据 | 构建领域种子（实体/关系）+ 语料 | `data/legal/legal_seed.json`、`data/kb/legal_corpus.txt` |
| 2. 图谱 Schema | 定义节点标签与关系类型 | `docs/design/测试数据域-本体Schema.md` |
| 3. 预定义查询 | 高频查询模板 | `components/predefined_cypher/legal_cypher_dict.py` |
| 4. Prompt | 路由/guardrails/生成 prompt | `lg_prompts.py`、`kg_sub_graph/prompts/` |
| 5. 范围描述 | 领域边界（用于 guardrails 拒答） | `application/agents/constants.py` 的 `SCOPE_DESCRIPTION` |
| 6. 工具描述 | 领域化的「何时用/不能用」 | `registry_init.py` |
| 7. 评估集 | 领域 golden 样本 | 评测集已于 2026-10-26 下线（工具链见 `evals/README.md`，需另建评测集） |
| 8. 配置 | 切换 collection / 语料 / 种子 | `.env`（`MILVUS_COLLECTION` / `KB_DATA_FILE` / `LEGAL_SEED_FILE`） |

> **架构无需改动**——这正是「分层 + 可插拔」的设计目标。

## 新增 HTTP 端点

**扩展点**：`agentix/interfaces/http/v1/`

```python
# interfaces/http/v1/my_feature.py
from fastapi import APIRouter, Depends

router = APIRouter(prefix="/my-feature", tags=["my-feature"])

@router.get("/")
async def list_items() -> list[dict]:
    return await _service.list_items()   # 调 application 服务，不写业务逻辑
```

在 `v1/__init__.py` 的 `api_router` 中 `include_router`。

**规则**（守卫：`test_p16_chat_service.py`）：
- 端点只做「参数校验 → 调服务 → 组装响应 → 错误映射」
- **不得**出现 ORM / CRUD 调用
- 错误通过 `AgentError` → HTTP 状态码映射（`domain/errors.HTTP_FATAL`）
