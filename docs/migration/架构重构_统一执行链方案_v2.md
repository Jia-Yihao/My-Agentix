## 2. 目标架构：一条执行链

```
API / SSE / Run API（仅协议转换）
→ Application（唯一入口：创建 Run）
→ Orchestrator（唯一控制流：Context → Plan → Execute → Observe → Verify → Replan/Finish）
→ Runtime（唯一状态 / Step / Budget / Lifecycle / Cancellation + Run registry）
→ Tool Gateway（唯一工具入口：Guardrails → Risk → Permission → HITL → Timeout → Retry → Trace）
→ Capabilities（Knowledge / Graph / SQL / Web / File / MCP / Memory-tools）
→ Infrastructure（Milvus / Neo4j / Redis / LLM / 外部服务）
```

| 层 | 职责边界 |
|---|---|
| L0 Interface | 只做协议转换，零 Agent 决策 |
| L1 Application | 创建/恢复/查询 Run，不实现 Planner/Tool 逻辑 |
| L2 Orchestration | 唯一推进权；LangGraph 只是 adapter |
| L3 Runtime | 唯一业务状态真源；checkpoint 仅编排恢复 |
| L4 Policy | Planner / Verifier / Guardrail / HITL：决定做什么、是否允许、是否完成 |
| L5 Tool Gateway | 唯一工具执行入口 |
| L6 Capabilities | 实现能力，不控制主循环 |
| L7 Infrastructure | 技术设施 |

一句话终态：请求进入应用层创建 Run，Orchestrator 驱动唯一 Plan→Execute→Observe→Verify 循环，Runtime 管状态预算生命周期，一切工具经 Gateway，RAG/Graph/SQL/Search/MCP 皆 Capability，LangGraph 只是编排实现，SSE/轨迹/Run API/评测消费同一条 Run/Event 真源。

## 3. 目标目录树（原稿 §13 的 v2 修订版）

```
agentix/
├── domain/
│   ├── agent/              # Task/Plan/Action/Observation/Verification 契约（M0 自 agent_types 拆入）
│   ├── runtime/            # Run/Step/Budget/Lifecycle 契约（M0 拆入）
│   ├── tool/               # ToolSpec/Risk/Permission 契约（M0 自 definitions 拆入纯类型）
│   ├── ports/              # 现状保留
│   └── policies/           # 现状保留（completion / error_classification 等值对象）
├── application/            # 用例与服务（chat_service / task_execution / knowledge_gateway…）
│   └── agents/             # 收缩：prompt、router adapter、业务 handler（lg_* 编排件迁出）
├── orchestration/          # M2 新建
│   ├── orchestrator.py     # 自 agent/core/loop.py 迁入（唯一推进权）
│   ├── executor.py         # 自 agent/executor.py 迁入（只调 Tool Gateway）
│   ├── langgraph/          # 自 application/agents/lg_* 迁入（adapter + builders）
│   └── strategies/         # single_step / retrieval / research / multi_agent
├── runtime/                # 现状强化 + ControlPlane 迁入（state_store / cancellation 落位）
├── policies/               # M3 新建
│   ├── planner/            # 自 agent/planner + agent/replanner 迁入
│   ├── verifier/           # 自 agent/verifier 迁入
│   ├── hitl/               # 自 agent/hitl + application 的 hitl_bridge 迁入
│   └── guardrails/         # 自 capabilities/tools/guardrails.py 迁入
├── tools/                  # M1 新建：自 capabilities/tools/** 迁入（gateway / registry / adapters）
├── capabilities/           # knowledge / graph / sql / web / file / mcp（工具件迁出后余量）
├── agent/                  # 收缩为 Context Provider 家：context / memory / skills / events / observer / hooks
│                           #（graph 占位删除；multiagent → orchestration/strategies；evolution 维持离线）
├── retrieval/              # 保留物理位置 = Knowledge Capability 宿主域（剥离自带 Agent 控制流）
└── infrastructure/ interfaces/ observability/ reliability/ security/ config/ crawler/
```

**与原稿的四处修订（v2 裁决）**：

1. **agent/ 不消失，但交出推进权**：原稿 §13 树没有 agent/，§14 却要求保留 loop.py——v2 裁决：编排三件（loop/executor + planner/verifier）分别迁入 orchestration/ 与 policies/，agent/ 收缩为 Context Provider 家（context/memory/skills/events/observer/hooks），符合「Memory 是 Context Provider」定位。
2. **policies/ 双层分界**：顶层 policies/ 放**有实现的横切策略**（planner/verifier/hitl/guardrails 的执行件）；domain/policies/ 保持纯契约值对象，不混。
3. **retrieval/ 不整体搬迁**：原稿只要求「不再自带 Agent 控制流」（§14），物理搬迁整个域包成本收益比失衡；以 M5 剥离其 ReAct 循环 + 收敛 router 达成同一目标。
4. **agentix/mcp/ 定为 shim**：实现已在 capabilities/mcp（Phase 6 迁移），M6 删除后 stdio 入口改为 python -m agentix.capabilities.mcp.server（README 同步）。

## 6. 统一架构守卫（12 条，唯一清单；总纲 §5 与原稿 §16 合并于此）

1. 同一 run_id 不允许同时存在两个 Orchestrator owner（含流式/非流式全路径断言）。
2. 所有 ToolCall（含记忆读写、检索、MCP）必须经过 Tool Gateway——白名单棘轮只减不增。
3. Capability 不得 import Orchestrator / Planner（分层单向）。
4. LangGraph adapter 不得直接写业务数据库状态；checkpoint 不得成为 Runtime 状态读取的唯一来源。
5. SSE event 必须来自统一 Run/Event stream（禁止 Chat SSE 与 Run API 各自拼事件）。
6. 应用层不得直接实例化 Neo4j / Milvus / MCP client。
7. 在线请求不得调用 Evolution promotion（只采集轨迹/反馈）。
8. 取消 Run 后必须最终进入 CANCELLED 或明确终态（真正打断 asyncio Task）。
9. Replan 次数受 Runtime Budget 控制；budget_exceeded 绝不悬挂。
10. 高风险（L1+）动作无 approver 时 fail-closed。
11. **LangGraph 导入白名单棘轮**（v2 新增）：仅登记在册路径可 import langgraph，新增即红；迁移期随 M 批次刷新集合。
12. **shim 目录断言**（v2 新增）：迁移期 = 白名单相等断言；终态 = 空集断言。

## 7. 门禁与纪律

- bug 顺手修：任何批次中发现的缺陷，能小修则当批修并加回归；大修另立编号并记 CHANGELOG。
