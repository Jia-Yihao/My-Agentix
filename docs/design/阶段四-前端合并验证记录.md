## 4. 阶段四连带修复（融合缺口）

1. **`TraceIdMiddleware` 不设 `request.state.request_id`**：R1 迁入的 retrieval 路由
   统一以 `request.state.request_id` 构造响应，原 Tracerag 后端的 RequestID 中间件
   融合时未带上 → **所有 `/api/v1/retrieval/**` 请求 500**。已在中间件内补设
   （trace_id ≡ request_id，同一链路 ID）。
2. **knowledge 前端 API 路径**：仍打融合前 `/api/v1/auth/...`；现由
   `api/config.ts` 的 `RETRIEVAL_API_PREFIX` 统一注入（13 文件 43 处调用剥离字面量），
   `withApiBase` 兼容直传完整旧路径。
3. 批量剥离前缀误伤 `config.ts` 常量值（`/retrieval`）→ 端到端登录 404 暴露后修正；
   教训：批量字符串替换必须把"注入常量"的文件排除在替换范围外。
