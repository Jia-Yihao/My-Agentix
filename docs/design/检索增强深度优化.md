## 2. 对标结论（生产 RAG SOTA + 三 Agent 产品）

- SOTA 管线（2026 收敛）：`Dense（BGE-M3 / Jasper）+ Sparse（BM25 / SPLADE-v3）并行 → RRF（k=10~60，Top200）→ Cross-encoder（BGE-reranker-v2-m3 / Cohere Rerank / Jina）α-rescore → TopK`；Milvus / ES 原生 hybrid；query 改写 + HyDE 治多轮意图漂移；评测按阶段归因 `Recall@5/MRR`。
- Codex：`claw-rag-service` 旁挂定位——检索只是工具之一，不抢主循环 C 位；本仓要补的正是“任务执行 C 位、RAG 辅助”叙事。
- Claude：按需加载（子目录 CLAUDE.md 触达才读）+ 子代理隔离检索（主上下文只回摘要）；对应本仓“检索结果进黑板统一融合、主上下文只留 evidence 摘要”。
- Hermes：检索只是工具（FTS5 fail-open）；核心是循环与记忆；故障语义 fail-open 保主链。
- 智谱系：多租户知识挂载 + 权限过滤下沉到检索层（行级可见性），检索必须先过权限再算分。

## 3. 目标架构（Capability 化）

```
Planner（只选能力：knowledge / graph / sql / web / file / mcp）
→ Tool Gateway（权限→风险→超时→重试→HITL→审计）
→ KnowledgeCapability：search / retrieve / rerank / evidence（统一出口）
     ├── Dense 路（向量：Milvus/FAISS/Qdrant 现有栈）
     ├── Sparse 路（BM25 / SPLADE，规划新建，不另起服务）
     ├── 融合层：RRF（免分数校准）/ 加权融合（可配 α）
     ├── 精排层：Cross-encoder rerank（现有 reranker 客户端统一，熔断 fail-open）
     └── 证据层：citation_verify + grounding_verify（由观测升级为门禁可配）
→ GraphCapability：entity_lookup / relation_query / path_query（Neo4j + 社区摘要）
→ SQLCapability：schema_inspect / generate_sql / execute_sql / validate_result（Wren/MySQL）
→ WebCapability：search / fetch / extract（外部搜索，受 allow_external 门控）
```

路由语义保留并工具化（原文/语义→A；实体多跳→B；混合→A 打底 B 补充；B 挂→A degraded），但执行收敛：L1 只做能力域选择不执行工具；L2 subgraph 降为 Strategy（Retrieval/Research/SQL）；L3 全部进 Gateway。

## 5. P1 真 Hybrid（召回质变）

- R-P1-1 Sparse 路：BM25（先行，零训练）+ SPLADE（可选，需 embedding 侧支持时再开），与现有 Dense 并行召回（规划新建模块，不新增外部服务；索引与现有文档入库链复用）。**【F1a 已落地】** `agentix/retrieval/infra/rag/sparse.py`：进程内 BM25（ASCII 词 + CJK 一元/二元分词，零新依赖），语料 = `agentix/retrieval/infra/repos/document_repo.py` 的 `get_chunks_by_kb`（与 dense 索引同 chunk_id 可融合去重）；按 kb_id TTL 缓存、fail-open 空结果；子闸 `RETRIEVAL_SPARSE_ENABLED`（默认关）。
- R-P1-2 RRF 融合：rank-only 融合（k 可配，默认 60；多轮场景 10），Top200 进精排；替代 `postgres else milvus` 丢分逻辑为跨通道归一融合（z-score / RRF 二选一，可配；默认 RRF 免调参）。**【F1a 已落地】** 纯函数 `agentix/domain/policies/rank_fusion.py`（`rrf_fuse`/`zscore_fuse`，domain 层供两侧共用不产生跨层引用）；Channel A 编排 `agentix/retrieval/usecases/retrieval_hybrid.py`（键 `RETRIEVAL_RRF_K`/`RETRIEVAL_FUSION_METHOD`/`RETRIEVAL_FUSION_ALPHA`/`RETRIEVAL_FUSION_TOP_N`）；Channel B `.../kb_nodes/local_search_node.py` 的 `fuse_local_channels`（键 `KB_LOCAL_FUSION_ENABLED`/`KB_LOCAL_FUSION_METHOD`，flag-off 仍 postgres-first）。
- R-P1-3 Rerank 默认开：Cross-encoder 对 Top20 精排取 TopK；熔断开路时保序 fail-open；`fusion_alpha` 加权融合保留为可配（语义重时调大 dense 权，术语重时调大 sparse 权）。**【F1a 已落地】** hybrid 链内 `RETRIEVAL_HYBRID_RERANK` 默认 true（只随总闸生效）+ `RETRIEVAL_RERANK_CANDIDATES`（默认 20）→ 截断 TopK；复用 `agentix/retrieval/infra/rag/rerank.py` 熔断 fail-open，熔断位记入阶段报告；`fusion_alpha` = `RETRIEVAL_FUSION_ALPHA`（zscore 通道权重）。
- R-P1-4 召回调优解耦：`fetch_k` 边界不依赖 `index.ntotal`（Milvus/Qdrant 无该属性时走配置值）；全局距离/分数阈值改为分通道阈值 + 融合后截断（避免单阈值抽空召回）。**【F1a 已落地】** dense 通道沿用既有距离/相似度阈值与有效性过滤；sparse 通道独立 `RETRIEVAL_SPARSE_MIN_SCORE`；融合输出只按 `RETRIEVAL_FUSION_TOP_N` 截断、**不再**复用 dense 距离阈值（RRF 分数与向量分数异口径）；`fetch_k` 无 `index.ntotal` 时恒走配置口径（`max(base, bounded)`）。
- R-P1-5 四阶段可观测：SSE/轨迹打点分解为 `rewrite → dense / sparse → rrf → rerank`（替代三粗段）；每阶段 TopK id + 耗时 + 熔断位，为评测归因供数。**【F1a 已落地】** 阶段报告经 ContextVar 旁路：轨迹 `rag.hybrid_stages` span（入口 kwargs 含每阶段 ms/hits/topk/熔断位）+ 结构化日志 + SSE 在检索预检后追加一帧 `detail.stages`（flag-off 仍只有 loading/retrieval/llm_generate 三段帧）。
- 灰度：影子跑（新链只打点不生效）→ 小流量 → 全量；golden 抖动超阈自动回滚旧链（发布门禁见 `.github/workflows/release.yml` preflight 与 `evals/quality_gate.py`（`evals/baselines/quality.json`））。

## 7. 验收

- 契约：双通道 `degraded` 语义单测；租户未传 fail-closed 单测；取消 Run 后检索 Task 真正中断（总纲守卫 8）。
- 行为：术语查询（编号/数据条目/专名）Sparse 命中率提升；语义查询 Dense 保持；混合查询 RRF Top1 正确且 runner-up 相关（抽查集）。
- 性能：P95 首 token 不劣化（rerank 只打 Top20）；熔断开路时延迟回落旧链水平。
- 文档纪律：规划新建路径不加反引号；引用现存路径以反引号给出（受 `tests/test_p41_doc_consistency.py` 校验）。

## 8. 后续质量提升计划（2026-10-10）

原则：不凭模型主观判断「更准」，先有可复现的人工金标与分阶段归因；每次只改一个变量，对比基线；所有新策略先影子/离线评估，再用既有 flag 小流量启用。当前 hybrid、query rewrite/HyDE、rerank 和 evidence gate 均已有独立开关，不应为了调参把默认路径一并改变。
