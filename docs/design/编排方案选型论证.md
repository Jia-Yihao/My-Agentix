## 0. 名词与判据

- **Workflow（确定性 DAG）**：分支与转移由**可枚举的显式判据**（常量表、正则、白名单、schema 校验、阈值比较）决定，不调用 LLM 做「开放判断」。
- **自主环节**：某一步的**转移/取值/内容**依赖 LLM 输出的开放判断，且其输出空间**不在编译期闭合**。
- 本文按「环节」而非「节点」划分：一个节点内可同时含自主判定与确定性判定，二者分开论证。

判定一个环节**是否真的自主**，看三点是否至少命中其一：
① LLM 输出直接决定路由目标；② LLM 输出直接决定内容（非固定格式装配）；③ 判据依赖运行期未知的数据分布。

## 2. 逐环节替代性论证

每个环节统一回答四问：**输入不确定性来源 / 用 Workflow 会怎样失败 / 自主性收益 / 代价与护栏**。

### 2.1 A1 L1 查询路由分类（`<A>/router.py:117-196`）

- **输入不确定性**：入口是任意自然语言，需在 7 个目标（`ALLOWED_TYPES`，`:91-99`：
  `general/additional/kb/graphrag/image/file/text2sql`）间择一。同一句话可跨类（「示例数据集 A关于异常金怎么规定」可落 kb 也可落 graphrag），
  分类边界是**语义**而非**词面**。
- **若用 Workflow 会失败**：唯一确定性做法是关键词表。代码里确有关键词表 `_heuristic_router`（`:66-72`，graphrag 13 词 + text2sql 5 词），
  但它是**兜底**不是主判定（见 3.1）。若把关键词表升为唯一判据，则：① 「《示例数据集 A》第五百七十七条说了什么」不含任何关键词 → 必然误落 kb；
  ② 每加一类意图就要重写词表，且词表交叉命中（「示例说明」既在 graphrag 词表又属 kb 范围）无法用优先级彻底消解；
  ③ 中文同义改写（「判几年」≈「评估」）无法穷举，**规则维护成本随长尾线性上升而覆盖率次线性**。
- **自主性收益**：LLM 直接读语义，一次性覆盖同义/省略/跨类组合；新增意图类型只需改 prompt（`lg_prompts.py`），不动分支代码。
- **代价与约束**：① LLM 可能返回非法 `type` → 代码以 `ALLOWED_TYPES` 做**白名单收敛**（`:130-144`）；
  ② LLM 调用失败 → 回退 `_heuristic_router` → 再回退 kb（`:113-124`）；
  ③ 用结构化输出 `Router`（`with_structured_output`，`:121`）约束格式，并由 temperature=0.0 router profile 降随机性（`:104-107` 注释）。

### 2.2 A2 信息不足时的追问决策（`<A>/guardrails.py:38-105`）

- **输入不确定性**：既要判「问题是否在库范围内」（scope，来自 `SCOPE_DESCRIPTION` + 动态 graph schema，`:52-57`），
  又要生成「追问什么」的自然语言。前者是二分类但边界由测试数据领域语义定义，后者是开放式生成。
- **若用 Workflow 会失败**：范围判定无法用关键词穷举——测试数据领域内问题形态（条文引用、数据分类、数据层级、责任竞合）无法枚举，
  且 schema 是**运行期从 Neo4j 拉取**的（`retrieve_and_parse_schema_from_graph_for_prompts`，`:54`），
  编译期不可知，确定性规则无法在编译期闭合。追问文案若模板化，则对「缺哪个槽位」的识别仍需语义理解。
- **自主性收益**：范围判定与追问内容一体化交给 LLM，随 schema 演进自动适配，无需为每个新节点/属性加规则。
- **代价与约束**：① 结构化输出 `AdditionalGuardrailsOutput`（`:24-28`）把决策收敛为 `end/proceed` 二值；
  ② `None` 输出兜底为 `proceed`（`:76-78`）；③ 内部判定链**故意不转发 config**（`:67-74`）以防编排 token 外泄——这是护栏，不是绕过。

### 2.3 A3 KB 子图 guardrails 判定 + 检索路由（`kb_nodes/`）

- **输入不确定性**：① `guardrails_node.py:35-39` 判「是否越界」（越界 → 固定话术，`:40-44`）；
  ② `router_node.py:40-45` 在 `local/external/hybrid` 三态间选择，并选 `milvus/postgres` 工具集（`:53`）。
  路由依据是「问题是否需要库外补充」，这取决于**本地是否有答案**——运行期数据分布问题。
- **若用 Workflow 会失败**：本地命中与否本质是运行期查询结果，编译期不可知；
  若硬编码「结构化问题走 postgres、语义问题走 milvus」这类规则，等于把 `KnowledgeService` 内部的召回逻辑复制到编排层，
  造成判据双源、易漂移。三态路由的分支组合（route × tools）无法用有限规则穷举而不重复实现检索语义。
- **自主性收益**：路由决策与检索策略解耦，检索源增减（`:53` 的 `{milvus, postgres}` 白名单）只需改一处。
- **代价与约束**：① `allow_external_search=False` 时**确定性钳制** external/hybrid → local（`router_node.py:47-52`）——
  自主决策被**配置闸门**收口；② 未指定工具时确定性兜底 `["postgres","milvus"]`（`:54-57`）；
  ③ 图级条件边 `guardrails_router`/`local_edge`（`kb_workflow.py:122-132`）对「空本地结果回落外部」是确定性判据。

### 2.4 A4 KG 子图任务分解与工具选择（`planner` / `tool_selection`）

**A4a 任务分解（`planner/node.py:42-71`）**
- **输入不确定性**：一个复合测试问题（「比较 A 条与 B 条对同一行为的责任规定」）需要拆成几个可独立检索的子任务，**拆几个、怎么拆**随问题形态变化。
- **若用 Workflow 会失败**：拆解规则若要穷举「并列/递进/比较/条件」等结构，等价于重写一个中文句法分析器；
  且拆解结果直接作为 `Send` 的 fan-out 数量（`edges.py:61-75`），分支数**运行期未知**，确定性 DAG 的静态拓扑无法表达变长 fan-out。
- **自主性收益**：`PlannerOutput`（`with_structured_output`，`node.py:38-40`）直接产出 `tasks` 列表，天然适配 map-reduce 扇出。
- **代价与约束**：① 结构化输出限定任务形状；② 空/失败时确定性兜底为「原问题单任务」（`:56-62`）；③ 扇出上限由 `max_attempts`/预算类开关约束（见方案 P0-2(c)）。

**A4b 工具选择（`tool_selection/node.py:134-253`）**
- **输入不确定性**：`predefined_cypher / cypher_query / text2sql / customer_tools(GraphRAG)` 四条路的边界是语义的：
  「有多少部测试数据规定了 X」是统计（→text2sql），「X 是什么」是释义（→GraphRAG），「列出某数据分类的数据条目」是模板（→predefined）。
- **若用 Workflow 会失败**：代码已给出**确定性快路径**（描述型关键词 `:57-70`→GraphRAG `:154-164`；SQL 型 `:31-55,73-77`→text2sql `:166-176`），
  说明「能确定性判的已确定性判」。但剩下的大量中长尾问题**没有稳定的词面特征**，只能靠 LLM 结合 `bind_tools`
  在工具 schema 间选择（`:205-235`）。若强行全规则化，`if/elif` 链会随工具数增长成 O(工具×意图) 的维护债。
- **自主性收益**：LLM 用工具 schema 的 description 做选择，新增工具**不改此节点**——由 `_TOOL_ROUTE_TABLE` 查表分发（`:88-111,223`）承接。
- **代价与约束**：① 未注册工具名 → 抛 `AgentError(TOOL_NOT_FOUND)`，**不静默降级**（`:95-111`）；
  ② LLM 未给工具 → 确定性回退 `cypher_query`（`:237-239`）；③ 路由表 + `available_tools` 集合做**白名单**闸门。

### 2.5 A5 Cypher 生成 / 校验 / 纠错（`cypher_tools/`、`text2cypher/`）

- **输入不确定性**：自然语言 → Cypher 的映射依赖**图 schema**（节点标签、关系类型、属性名），
  而 schema 在代码中不出现（仅 `graph.schema` 运行期可读，`utils.py:372`），是**跨库未知量**；
  且用户可能指代库中不存在的实体（数据分布未知）。
- **若用 Workflow 会失败**：自然语言 → Cypher 无法用规则模板穷举（同义关系、多跳路径、聚合/排序组合爆炸）；
  这正是 text2cypher 的经典不可规则化点。此外「映射失败」（值不存在）与「语法失败」需要区别对待，
  前者依赖数据分布，规则无法预判。
- **自主性收益**：生成节点用 few-shot 示例（`LegalCypherRetriever.get_examples`，`utils.py:365-367`）+ schema 注入（`:372`），
  可泛化到未见过的问法；纠错节点（`utils.py:456-465`、`correction/node.py:40-58`）用错误信息 + schema 反向修复，避免穷举错误类型。
- **代价与约束**（本环节护栏最密，体现「自主外层包确定性内层」）：
  ① **只读闸门（黑名单）**：`validate_no_writes_in_cypher_query`（`utils.py:326-348`）复用 `constants.WRITE_CLAUSES`
  （`constants.py:4-18`，含 `CREATE/DELETE/SET/MERGE/DROP/CALL/APOC.` 等）；**执行侧二次拦截**（`execution/node.py:48-61`）防止末次尝试放行；
  ② **语法校验确定性**：`EXPLAIN` 试跑（`utils.py:93-115`）；
  ③ **关系方向确定性纠正**：`CypherQueryCorrector`（`utils.py:118-148`）；
  ④ **标识符白名单**：`_IDENTIFIER_PATTERN` 仅允许合法标识符 f-string 插值（`validators.py:29-36`）；
  ⑤ **无 LLM 的 schema 校验**（enum/range）：`validate_cypher_query_with_schema`（`utils.py:230-323`，注释明示 "does not use an LLM"，`:237`）。
  即：**纠错在自主侧，放行在执行侧由确定性闸门把关**。

### 2.6 A6 幻觉校验（`orchestration/langgraph/lg_builder.py:193-229`）

> 2026-10-30 实测更正（只更正锚点时点，不动本节任何结论）：标题沿用的 `193-229` 是登记时点的旧行号快照，`check_hallucinations` 的真身现起 `agentix/orchestration/langgraph/lg_builder.py`:160、至 `:186`（复跑 `grep -n "^async def check_hallucinations" agentix/orchestration/langgraph/lg_builder.py` 与 `grep -n "^def create_message_window_node" agentix/orchestration/langgraph/lg_builder.py` 定界）。

- **输入不确定性**：判断「答案是否被检索文档支持」（`GradeHallucinations` 二值）需要对**未结构化文档**与**自由文本答案**做 entailment，
  文档内容运行期才确定，无固定 schema 可供规则匹配。
- **若用 Workflow 会失败**：规则化只能做字符串包含/引用比对，无法覆盖改写、归纳、跨句推理；引用比对又会把「正确概括」误判为幻觉。
- **自主性收益**：以 temperature=0.0 + 结构化二值输出（`:191,202-205`）做一次低成本一致性检查，泛化所有领域。
- **代价与约束 / 现状**：该节点**当前未接线到主图**（`build_graph` 只注册 10 节点，不含它；全仓无其他运行期引用）。
  因此现阶段它不构成运行期成本，但也**尚未产出收益**——**这是有意留档，不是待办**：代码注释自 2026-09 审计起把它标为
  `DEAD-CODE(P2-5)｜处置=保留·有意不接线`（`agentix/orchestration/langgraph/lg_builder.py`，`check_hallucinations` 定义前；不接线的理由写在注释里：接线会给每次图执行新增一次 hallucination 校验 LLM 调用，属运行期行为变更 + 成本变更，需独立评估；绊线 `tests/test_p24_deadcode_marking.py` 钉死"标注 + 运行期断言未接线"形态）。
  原句「建议列入后续接线项」（2026-10 口径）已被代码意图取代：**不接线是现口径**；若未来要排期接线，须限定 `documents` 来源为可信检索结果，并以确定性来源（溯源卡片 `sources`）优先。

### 2.7 A7 运行时写代码执行（`application/agents/code_handler.py`）

- **输入不确定性**：解法是**运行期才确定**的一段程序——「怎么算、怎么拼、怎么遍历」没有固定 schema，也没有一张能穷举的表；同一句提问在不同数据分布下的正解不同。
- **若用 Workflow 会失败**：确定性编排能做的只是"调一条已存在的工具"，而本环节的前提恰恰是**任务尚不存在对应工具**——把每种解法预先翻译成既有工具调用，正是本机制要绕开的那道翻译。
- **自主性收益**：LLM 直接产出可执行代码（temperature=0.0 的结构化输出 `CodeDraft`），跑完看真实 stdout/stderr 再改一版；总尝试轮数（含首次执行）由 `CODE_EXEC_MAX_ROUNDS` 封顶。
- **代价与约束 / 现状**：自主性**必须**配确定性护栏才放行——① 草稿入参在执行点**之前**校验（长度/类型/超时夹紧，错误信息不回显代码正文）；② 执行经 `ToolExecutor` 治理链（权限 → 风险 → HITL → 沙箱档位 → 超时）；③ 治理拒绝与沙箱不可用一律**终局**，不自愈（重试换不来一个实现）；④ 汇总环节 fail-open 回落原始 stdout；⑤ 节点**无条件注册、flag 门控可达性**（`CODE_EXEC_ENABLED=false` 时路由不产 `code-query`，与基线逐位等价）。机制口径见 `.qoder/rules/code-exec.md`。

## 3. 反向论证：哪些环节**应该**是确定性 Workflow

「能 Workflow 就 Workflow」是本方案的对称约束。以下环节**已实现**为确定性逻辑，且**不应**引入 LLM：

| 编号 | 环节 | 代码位置 | 为何必须确定性 |
|---|---|---|---|
| W1 | 路由兜底 `_heuristic_router` | `<A>/router.py:74-103` | 关键词→类型是**有限映射**；作为 LLM 失败的第 2 层兜底，必须零成本、零随机（**更正见附录 B**） |
| W2 | Cypher 只读闸门 | `constants.py:4-18` + `utils.py:326-348` + `execution/node.py:48-61` | 安全边界**不可交给概率模型**；黑名单子串匹配是唯一可信判据 |
| W3 | 标识符注入白名单 | `validators.py:29-36` | 防 f-string 注入（如 `) DETACH DELETE //`），正则闭合、可证明 |
| W4 | 预定义查询命中 | `predefined_cypher/node.py:48-104` | TF-IDF 余弦匹配（`utils.py:48-74`）+ 阈值 0.5；命中即**不走文本生成**，走模板，省一次 LLM 且结果可控 |

**结论**：安全/契约/装配三类**一律确定性**；LLM 只出现在「输入空间不闭合」的判定与生成处，且外层都被白名单/校验器/兜底包裹。

## 4. 判据表（可操作决策规则）

对任一「新环节」，按顺序判定。**默认落 Workflow；只有明确命中右侧条件才允许上自主环节。**

| 条件 | → Workflow（确定性 DAG） | → 自主环节（LLM + 护栏） |
|---|---|---|
| 分支能否穷举 | 分支可穷举（≤ 一张常量表 / 正则 / 白名单） | 分支随语义/长尾变化，不可穷举 |
| 判定能否确定性表达 | 可用正则/阈值/schema/enum/EXPLAIN 等闭合判据 | 需语义/ entailment / 跨库 schema 理解 |
| 输入空间是否闭环 | 编译期已知（固定槽位、有限类目） | 运行期未知（自然语言、数据分布、外部文档） |
| 分支数是否静态 | 拓扑固定（边数编译期确定） | fan-out 变长（子任务数运行期决定） |
| 出错代价 | 出错可接受或有确定兜底 | 出错代价高 → **必须**配确定性护栏才放行 |
| 维护成本 | 规则少量且稳定 | 规则随长尾膨胀，维护成本 > 收益 |
| 结论 | 写进代码/常量表，加单测 | 结构化输出 + 白名单 + 校验器 + 兜底 |

**强制护栏清单**（自主环节缺一不可）：① 结构化输出 schema 收敛取值域；② 输出白名单/枚举校验；
③ 失败路径确定性兜底；④ 写/危险动作前独立确定性闸门；⑤ 角色/温度差异化 profile（见 `llm_factory.py:18,43-49`）。
